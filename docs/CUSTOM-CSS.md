# 自定义 CSS 与设计令牌

> 这是 AriaNg-Next 相对 AriaNg 最大的区别：**你不改源码、不 fork，也能把面板改成自己顺眼的样子。**

---

## 一、为什么你的 CSS 一定能生效

普通做法里有个经典陷阱：

```
组件层：  .an-card { border-radius: 8px }    → 特异性 (0,1,0)
你的层：  .an-card { border-radius: 20px }   → 特异性 (0,1,0)
```

特异性相同，谁生效取决于**源码顺序** —— 组件样式写得更晚就赢。
这对用户来说太脆弱了：换个版本、改个文件顺序，你的样式就"失效"了。

本项目用 CSS 原生的**层叠层**从根上解决：

```css
@layer reset, tokens, components, user;
```

层与层之间的优先级**高于**选择器特异性。于是：

- 你的 CSS 永远写在 `user` 层 → **永远赢**，不需要 `!important`
- 组件层内部依然可以自由使用隔离写法，互不干扰

引擎在你保存时自动完成包装（`src/core/css/engine.ts` 的 `buildUserLayer()`），
你只管写正常的 CSS。

## 二、怎么用

打开「外观与 CSS」页面，在文本框里写 CSS，**保存即生效，无需刷新**。

```css
/* 改圆角 */
.an-card {
  border-radius: 20px;
}

/* 改进度条颜色 */
.an-progress__fill {
  background: linear-gradient(90deg, #f59e0b, #ef4444);
}

/* 改侧栏宽度 */
:root {
  --an-sidebar-width: 280px;
}

/* 改字体 */
.an-app {
  font-family: 'Source Han Serif SC', serif;
}
```

## 三、作用域

| 模式 | 行为 |
|---|---|
| **仅面板容器内**（默认） | 用 `@scope (.an-app)` 把规则限制在面板内部，`body { … }` 之类的规则不会影响外部 |
| **全局生效** | 规则直接作用于整个文档 |

> 浏览器不支持 `@scope` 时会自动降级为全局生效，界面会明确提示。
> 在容器作用域下，`:root` 不会匹配 —— 想改令牌请用下方的令牌编辑器，或切到全局作用域。

## 四、常见问题

**Q：CSS 写错了会怎样？**
保留上一份可用的样式，并在编辑器下方显示错误与行号，界面不会崩。
校验用的是浏览器自己的 CSS 解析器（`CSSStyleSheet.replaceSync`），所以判断很准。

**Q：能不能导出 / 分享？**
能。「导出 CSS」会生成一个 `.css` 文件，包含令牌覆盖与自定义规则，可以直接分享给别人。

**Q：会跟着主题走吗？**
会。令牌覆盖写在 `tokens` 层，主题切换只是换令牌值，两者互不冲突。

**Q：怎么知道有哪些类名可以改？**
在浏览器 DevTools 里搜 `.an-` 就能看到真实 DOM 上的类名；
命名规则是 `.an-{块}__{元素}--{修饰}`，例如 `.an-task-row__name`。

## 五、设计令牌

三套预设共用同一份结构，只替换令牌值：

| 主题 | 说明 |
|---|---|
| **Light** | 默认，白天 / 文档场景 |
| **Dark** | 默认，夜间 / NAS 常驻大屏 |
| **Glass** | 可选，半透明，需要背景图，低性能设备自动降级 |

常用令牌：

```css
--an-accent         /* 文字主色 */
--an-accent-fill    /* 品牌填充色 */
--an-bg             /* 页面背景 */
--an-surface        /* 卡片表面 */
--an-radius-md      /* 圆角 */
--an-text-md        /* 正文字号 */
--an-sidebar-width  /* 侧栏宽度 */
--an-drawer-width   /* 抽屉宽度 */
```

令牌编辑器里改的值会写回 CSS 变量并持久化；也可以直接在自定义 CSS 里用 `:root` 覆盖（全局作用域下）。

## 六、配色系统

主色取自 **MiniMax 控制台的粉色 `#f2acba`**，但不能直接拿它当文字色 ——
`#f2acba` 在白底上对比度只有 **1.84:1**，连大号文字都达不到 WCAG AA。

所以拆成了两个角色：

| 令牌 | 值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--an-accent` | `#B8435F` | 文字主色：链接、激活态、图标 | 白底 **5.24:1**，粉色浅底 **4.65:1** ✅ |
| `--an-accent-fill` | `#F2ACBA` | 品牌填充色：主按钮、Logo、进度条渐变端 | 配深墨字 **9.50:1** ✅ |
| `--an-accent-contrast` | `#2A1219` | 填充色上的文字 | — |

另外两条借鉴 MiniMax 官网的手法：

1. **底色不用冷灰，改用带粉调的暖中性**（亮色 `#FAF7F8` / 暗色 `#161113`），整体更柔和；
2. **阴影带品牌色** —— MiniMax 用紫调阴影 `rgba(44,30,116,.16)`，这里换成粉调 `rgba(92,26,48,.16)`，让"深度"也属于品牌。

形状语言也跟着走 MiniMax：**药丸形**（9999px）用于导航与切换类控件，标准圆角用于 CTA 按钮 —— 这是它最容易被认出来的特征。

暗色主题里粉色直接当文字色（在 `#161113` 上有 10.13:1）；
毛玻璃主题的底图是浅粉→洋红渐变 —— 因为底图太暗、60% 白叠上去只会发灰发浑。

全部对比度都是用脚本逐对算过的，改色值后可以直接重跑验证。

## 七、字体约定

界面上的**绝大部分文字都不该用等宽字体** —— 等宽是"代码"的视觉语言，
用在标题、徽章、版本号这类显眼位置会显得很"机器味"。

| 用无衬线 | 用等宽 |
|---|---|
| 标题、副标题、版本号 | CSS 编辑器 |
| 徽章、计数、状态标签 | 令牌变量名 |
| 表格数值（用 `tabular-nums` 对齐） | 行内代码 |
| 输入框内容 | |

数字对齐用 `font-variant-numeric: tabular-nums`，视觉上同样是等宽对齐，但不引入"代码感"。

中文正文字体栈：`Inter → 苹方 → 思源黑 → 微软雅黑 → 等线`。
